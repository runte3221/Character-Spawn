# 実装設計書・開発憲章: シーン・配置管理（Scene）アーキテクチャ構想

## 1. プロジェクトの究極目的と開発憲章（目的のぶれ防止）

### 【本来の目的】
**「Character Spawn」は、単なるキャラクター召喚ツールではなく、ゲーム内に生き生きとしたカスタムシーン（世界観・空間演出・NPC・仲間たち）を構築し、プレイヤーが没入できる究極の配置・演出プラグインである。**

- **第1工程で達成したこと**:
  - キャラクターという「生命の器（外見・体型・モデル・骨格）」を、あらゆるソース（Glamourer, Penumbra, MCDF, NPC, Monster, Customize+）から完璧にエラーなく描画する基盤を確立。
- **第2工程で目指すこと**:
  - それらのキャラクターを世界に配置し、生きているかのように佇ませ、プレイヤーの接近に反応させ、空間そのものを創造する（シーン・配置管理）。

### 【開発憲章: 4大鉄則】
1. **第1工程のコア（外見・スポーン描画パイプライン）の完全凍結**:
   - `CharacterTemplate`、`ApplyAppearanceDirect`、`CustomizePlusIpc` 等の完成済みコードには手を加えない。
   - シーン機能は「既存の完成したテンプレートを参照（ID）して呼び出す上位レイヤー」として構築し、下位のコアを改変しない。
2. **完全モジュール隔離（Failure Isolation）**:
   - モーション、ネームプレート、サウンド、アセット消去などの機能は、すべて独立したサービス（C#クラス）として設計する。
   - ある機能に不具合や例外が発生しても、他の機能やキャラクターのスポーン自体を巻き込んでクラッシュさせない（個別 `try-catch` と状態の完全隔離）。
3. **安全な公式 API と低侵襲アプローチの徹底**:
   - ネームプレート制御には Dalamud 公式の `INamePlateGui` を使用し、危険なメモリ直書きを行わない。
   - モーション制御にはゲーム内標準の `ActionTimeline` を使用し、ゲームエンジンの安定性を最優先する。
4. **段階的・反復的なリリースと実機検証**:
   - 一度にすべてを実装せず、Phase ごとに小さく確実な単位で実装・検証・リリースを重ね、手戻りをゼロにする。

## 3. 各機能の詳細仕様設計

### ① 配置管理 (`PlacementService`)
- **データ構造**:
  ```csharp
  public class SceneActorPlacement
  {
      public Guid PlacementId { get; set; } = Guid.NewGuid();
      public string CharacterTemplateId { get; set; } = string.Empty; // 第1工程のテンプレートID
      public Vector3 Position { get; set; }
      public float Rotation { get; set; }
      public bool IsSpawned { get; set; }
      // モーション・ネームプレート設定への参照
      public SceneActorMotionConfig Motion { get; set; } = new();
      public SceneActorNamePlateConfig NamePlate { get; set; } = new();
  }
  ```
- **仕様**:
  - シーン単位で複数の `SceneActorPlacement` を保持。
  - テリトリー（現在のゾーンID）とシーンを紐付け可能。
  - 一括スポーン（全配置キャラを召喚）および一括デスポーン。
  - プレイヤーの現在位置への配置ボタン、ドラッグ移動／ギズモ対応（将来）。

### ② モーション・アニメーション制御 (`AnimationService`)
- **ActionTimeline モーション再生**:
  - ゲーム内約1万種のアニメーションキー（プレイヤー、NPC、モンスター）から選択。
  - ループ設定: 単発再生（終了時停止）または無限ループ（常時再生）。
- **表情（Facial）制御**:
  - 表情専用スロットへのタイムライン注入により、笑顔、怒り、驚きなどを固定。
- **視線追従（LookAt / Head Tracking）**:
  - パペットの `TargetId` に `LocalPlayer.GameObjectId` をセットすることで、ゲームエンジンの IK を利用して自キャラの動きに合わせて自然に首と視線を追従。
  - オプション: `自キャラを追従` / `固定（正面）`。
- **自キャラ接近トリガー（Proximity Reaction）**:
  - 待機モーション（通常時）とリアクションモーション（接近時）を設定。
  - プレイヤーとの距離（例: 3m 以内）に入ると自動でリアクションモーションへ遷移。
  - 離れると元の待機モーションへ自然復帰。
  - 再発火クールダウン設定（連続で手を振り続けないよう制御）。

### ③ ネームプレート・称号制御 (`NamePlateService`)
- **Dalamud 公式 `INamePlateGui` の完全活用**:
  - `INamePlateGui.OnNamePlateDraw` イベントをフック。
  - パペットの GameObjectId と照合し、該当パペットのネームプレートを操作：
    - `args.IsVisible = false`: ネームプレート全体を非表示。
    - 称号（Title）の個別表示／非表示。
    - 任意のカスタム称号（例: "<街角の商人>", "<森の案内人>" 等）の表示。

### ④ サウンド制御 (`SoundService`) 【将来拡張】
- プレイヤーとの距離を計算し、接近時にオーディオをトリガー。
- 距離減衰（近づくと大きく、離れると小さく）によるリアルな 3D 空間音響演出。

### ⑤ アセット表示／非表示 (`AssetHiderService`) 【将来拡張】
- Stagehand / Brio 準拠のスポイト機能。
- カメラからレイキャストを行い、マップ上の背景オブジェクト（Sgb/Prp/Housing）を選択。
- `DrawObject->DisableDraw()` または可視フラグ操作により、任意のマップ小道具を一時的に非表示化。
- シーンデータとして「消去したアセット一覧」を保存・復元。
