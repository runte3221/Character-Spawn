# 技術記録・設計ウォークスルー: シーン・配置管理（Scene）構想と目的維持ガイドライン

## 1. 第1工程（キャラクター基盤）の完了総括

本プロジェクトは、v0.1.54.0 に至る徹底的な実機検証と逆アセンブル解析を通じて、あらゆるカスタムキャラクターの生成・描画において最高レベルの安定性を確立しました。

### 確立された基盤の堅牢性
1. **Glamourer & Penumbra 併用**:
   - 先行 Redraw を排除し、自キャラの武器やモデルのチラつきがゼロに（v0.1.54.0）。
2. **CustomizePlus**:
   - 一時プロファイル IPC への完全移行により、ユーザー設定ファイルを一切汚染しない完全メモリ制御を達成（v0.1.52.0）。
3. **人型NPC**:
   - HDM 完全準拠の Base64 圧縮データ渡し（`0 ticks`）と DrawObject 再構築により、連続スポーンでも自キャラ化や外見ズレが起きない（v0.1.51.0）。
4. **Monster / Demihuman (16,243種)**:
   - RFC 4180 準拠の CSV 解析により、フォーギヴン・テスリーン等のボス・Mob 全種類が正常ロード（v0.1.53.0）。

## 2. 第2工程「シーン・配置管理（Scene）」の技術的検証記録

### (1) アニメーション・モーション制御
- **検証結果**: `ActionTimeline` を用いたアニメーション再生は、HDM の `AnimationService` と同等のアプローチで完全可能。
- **自キャラ視線追従 (LookAt)**: パペット構造体の `TargetId` にプレイヤーの `GameObjectId` を設定することで、ゲームエンジン内蔵の頭部・視線 IK が自動的にプレイヤーを追尾することを確認。
- **接近トリガー (Proximity Reaction)**: `Vector3.Distance` によるプレイヤーとの距離監視を行うことで、待機モーション（腕組みなど）から接近時リアクション（会釈、手を振るなど）への自動遷移が軽量かつ自然に実現可能。

### (2) ネームプレート・称号制御
- **検証結果**: Dalamud 公式の `INamePlateGui` を利用可能。
- `OnNamePlateDraw` イベント内でパペットの `GameObjectId` を照合し、`args.IsVisible = false` とするだけで、ゲームクラッシュのリスクなく安全にネームプレートや称号を非表示・改変できることを確認。

### (3) 将来拡張（サウンド・アセット消去）
- **サウンド**: 距離減衰（3D空間音響）を用いた接近時再生が可能。
- **アセット消去**: Stagehand / Brio と同一のレイキャスト・スポイト判定と `DisableDraw()` により、マップ上の椅子や机などの特定オブジェクトを一時的に非表示化可能。

## 3. 本来の目的がぶれないための「開発ガイドライン」

開発が進み、コードの改修や不具合対応を繰り返す中で、**本来の目的から逸脱したり、既存のコアを破壊しないための指針**です。

### ガイドライン 1: 「シーン」は「キャラクター」の上位コンテナであること
- シーンはキャラクターテンプレートそのものを書き換えてはなりません。
- 「どのテンプレート」を「どこに」「どんなモーションで」配置するかという、**外側の配置指示書**としてのみ振る舞う必要があります。

### ガイドライン 2: 不具合発生時の「隔離原則」
- モーションで不具合が起きた場合は `AnimationService` のみを見直すこと。
- ネームプレートで不具合が起きた場合は `NamePlateService` のみを見直すこと。
- **絶対に下位の `ActorManager` や Glamourer/Penumbra/CustomizePlus パイプラインに原因を求めたり、コアコードを改変しないこと**。

### ガイドライン 3: 演出の主役は「世界観と没入感」
- シーン管理の真の価値は、単に人形を並べることではなく、「**まるでその世界に昔から住んでいるかのように NPC や仲間が自然に佇み、プレイヤーの存在に反応する空間を作る**」ことにあります。
- 接近リアクションや視線追従、ネームプレート非表示、将来の環境音演出は、すべてこの「世界観と没入感」を極限まで高めるために設計されています。
