# 技術記録・開発運用ウォークスルー: シーン・配置管理（Scene）フェーズ別実装・検証ガイド

## 1. 開発方針と環境隔離の確認

本ドキュメントは、シーン管理（Scene）の実装を進める各フェーズにおいて、開発者とテスターが参照すべき**具体的な操作手順、検証シナリオ、およびトラブルシューティング手順**をまとめた運用ガイドです。

---

## 2. フェーズ別 実装・検証ウォークスルー

### 【Phase 1: シーン・複数体配置基盤】
1. **実装ステップ**:
   - `Models/SceneData.cs` を作成（シーン、配置アクターのデータ構造）。
   - `Managers/SceneManager.cs` を作成（複数 COM スロット割り当て、一括スポーン/デスポーン）。
   - `UI/SceneTab.cs` を作成（ImGui でシーン一覧・配置編集画面を実装）。
2. **実機検証シナリオ (QA-1)**:
   - **シナリオ 1-A (単体〜複数体スポーン)**:
     - 任意のハウスやフィールドで、Scene タブを開く。
     - 「新規シーン」を作成し、テンプレート（例: Lyle Nude、ミューヌ、テスリーン等）を 3 体追加。
     - それぞれ異なる座標（プレイヤー現在位置から少し離れた場所）を設定。
     - 「シーンをスポーン」をクリックし、3 体が同時に指定位置に出現することを確認。
   - **シナリオ 1-B (一括デスポーンとクリーンアップ)**:
     - 「シーンをデスポーン」をクリック。
     - 3 体すべてが消去され、CustomizePlus 設定ファイルにゴミが残らないこと、Penumbra コレクションが解除されていることを確認。
   - **シナリオ 1-C (テリトリー移動テスト)**:
     - 3 体スポーンした状態で別エリアへテレポ。
     - 移動先でエラーログが出ず、古いアクターが綺麗に消去されていることを確認。

---

### 【Phase 2: モーション・視線・表情・接近リアクション制御】
1. **実装ステップ**:
   - `Services/AnimationService.cs` を作成（`ActionTimeline` 注入、ループ管理）。
   - 接近トリガーエンジン（Framework 更新時の距離計算ループ）を実装。
   - Scene タブにモーション選択・表情選択・接近リアクション設定 UI を追加。
2. **実機検証シナリオ (QA-2)**:
   - **シナリオ 2-A (無限ループと表情固定)**:
     - アクター A に「座る (Sit)」モーションと「笑顔 (Smile)」表情を設定しスポーン。
     - 数分間観察し、立ち上がったり表情が戻ったりしないことを確認。
   - **シナリオ 2-B (視線追従 LookAt)**:
     - アクター A の「自キャラを追従」を ON にする。
     - プレイヤーが周囲を歩き回ると、首と視線がプレイヤーを追従することを確認。
   - **シナリオ 2-C (接近リアクション)**:
     - 通常モーション:「腕組み (CrossArms)」。
     - 接近リアクション:「手を振る (Wave)」、検知距離: 3.0m。
     - プレイヤーが 5m から 2m に近づいた瞬間に手を振る動作を開始することを確認。
     - 再び 5m に離れると、腕組みポーズにスムーズに戻ることを確認。

---

### 【Phase 3: ネームプレート・称号制御】
1. **実装ステップ**:
   - `Services/NamePlateService.cs` を作成（`INamePlateGui.OnNamePlateDraw` フック）。
   - Scene タブにネームプレート設定 UI を追加。
2. **実機検証シナリオ (QA-3)**:
   - **シナリオ 3-A (非表示テスト)**:
     - アクター A のネームプレートを「非表示」に設定してスポーン。
     - アクター A の頭上から名前・HPバーが完全に消え、背景に溶け込むことを確認。
   - **シナリオ 3-B (称号上書きテスト)**:
     - アクター B の称号を「<街角の商人>」に設定。
     - 頭上に「<街角の商人> アクター名」と綺麗に表示されることを確認。
   - **シナリオ 3-C (他アクターへの非干渉)**:
     - 周囲の他プレイヤーや正規 NPC のネームプレートが一切影響を受けていないことを確認。

---

## 3. 万が一のトラブルシューティング・不具合隔離マニュアル

もし開発・テスト中に予期せぬ不具合が発生した場合、**原因を即座に特定し、第1工程のコアを保護するための診断手順**です。

| 症状 | 疑うべき箇所 | 確認・対処手順 |
|---|---|---|
| **パペットが 1 体しかスポーンしない** | COM スロットの枯渇、または Index 重複 | `ClientObjectManager` のスロット割り当てログを確認。Index 200 以外に 201, 202... が確保されているか確認。 |
| **モーションが途中で立ち姿に戻る** | `AnimationService` のループ監視 | ゲームエンジンのアニメーション終了イベントが検知できているか、`LoopReplay` タイマー間隔を確認。 |
| **自キャラの視線追従が動かない** | `TargetId` の設定値 | パペットの `TargetId` に `localPlayer.GameObjectId` が正しく代入されているかログ確認。 |
| **ネームプレートが消えない** | `INamePlateGui` のマッチング不一致 | フック内の `GameObjectId` とパペットの実 ID が一致しているかデバッグ出力で確認。 |
| **外見や骨格が崩れた** | **※第1工程のコアは触らないこと！** | モーション再生時のスロット（Base/Upper/Facial）がモデル構造と干渉していないか、`AnimationService` 側で注入スロットを調整。 |
